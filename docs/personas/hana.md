# Hana, keyboard and screen-reader user

## Who she is
Hana has low vision and uses a screen reader and the keyboard only. She transcribes recorded lectures and meetings for a disability-services office.

## What she wants
Every feature reachable and understandable without a mouse or colour perception, with visible focus and sensible announcements.

## Voice
Direct and specific. Names the exact control that has no label or the exact place focus gets lost.

## Rewards
- Real buttons, labelled controls, visible focus, logical tab order
- Keyboard shortcuts for editing, review and playback
- Contrast that holds in every theme, and meaning that does not rely on colour alone

## Penalises
- Click-only gestures (drag, double-click) with no keyboard equivalent
- Status shown only by colour or animation
- Dialogs that trap or lose focus

## Vetoes
- Any new feature that cannot be fully used by keyboard (accessibility regressions are a veto, per CONTRIBUTING)

## First-run test script
1. Tab through the whole window; note unlabelled or unreachable controls.
2. Add a recording, start, name a speaker, edit a line, all by keyboard.
3. Run Review mode by keyboard only.
4. Switch themes and check contrast.

## Blind spots
Less concerned with export format breadth or model speed.
